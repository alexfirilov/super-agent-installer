# GAP-7: Popularity / rating sources not used before, and a repeatable ranking method

Date of every observation in this report: **2026-09-17** (UTC timestamps given where they matter). All numbers were fetched by the commands quoted; nothing is reconstructed. Companion files (same directory):

- `gap-7-ranking.csv` — dated popularity snapshot + score for 104 items (must-have/recommended first, then the long tail from the manifest and digests).
- `gap-7-claude-plugins-official-installs-2026-09-17.csv` — the full 308-plugin official-marketplace catalog with `unique_installs` (the claude.com/plugins long tail).
- `gap-7-mcp-registry-latest-2026-09-17.tsv` — all 32,849 latest-version entries of the official MCP Registry (name, version, status, updatedAt, package types, remote types, repo).
- Scripts in `../g7/` (scratchpad): `paginate.sh` (registry dump), `gh_snapshot.py` (stars + last commit, no API quota), `items.py` (item list with identifiers), `rank.py` (formula and CSV writer).

## 1. Key findings (TL;DR)

1. **The official MCP Registry has no popularity, download, rating or star field at all.** Its schema (`openapi.yaml`, 2026-09-17) exposes only `status` (active/deprecated/deleted), `publishedAt`, `updatedAt`, `isLatest`, `statusMessage` under `_meta["io.modelcontextprotocol.registry/official"]`. Search is `search=<substring of name>` only (so `search=github` returns the whole `io.github.*` namespace). It is an identity/manifest source (canonical `packages[]` and `remotes[]`), not a ranking source. Size on 2026-09-17: **32,849 latest-version entries** (32,502 active, 347 deprecated), 329 pages of 100, full dump took 10.6 min (13:30:40Z -> 13:41:16Z).
2. **Neither Claude Code nor Codex consumes the registry.** code.claude.com/docs/en/mcp points to the Anthropic Directory (`claude.ai/directory`) and manual `claude mcp add`; learn.chatgpt.com/docs/extend/mcp lists "Examples of useful MCP servers" and manual config. Neither page mentions registry.modelcontextprotocol.io.
3. **Recommended servers in the registry** (all `active`, `version=latest`): context7 `io.github.upstash/context7` 4.1.1 (npm `@upstash/context7-mcp` 4.1.1 + mcpb + remote `https://mcp.context7.com/mcp`); playwright `io.github.microsoft/playwright-mcp` 0.0.81 (npm only, no remote); github `io.github.github/github-mcp-server` 1.12.2 (oci `ghcr.io/github/github-mcp-server:1.12.2` + remote `https://api.githubcopilot.com/mcp/`); exa `ai.exa/exa` 3.1.3 (remote `https://mcp.exa.ai/mcp` only, entry dated 2025-12-05 while npm is 3.4.1); serena `io.github.oraios/serena` **1.5.3 (2026-05-26) — stale vs PyPI 1.7.0 (2026-08-09)**; grafana `io.github.grafana/mcp-grafana` v1.5.0 (oci `docker.io/grafana/mcp-grafana:1.5.0` + remote `https://mcp.grafana.com/mcp`, updated 2026-09-17); kubernetes `io.github.containers/kubernetes-mcp-server` 0.0.66 (npm + pypi + oci `ghcr.io/containers/kubernetes-mcp-server:v0.0.66`); chrome-devtools `io.github.ChromeDevTools/chrome-devtools-mcp` 1.9.0 (npm `chrome-devtools-mcp` 1.9.0 = npm latest, no remotes, published/updated 2026-09-08T09:53:46Z — verified by exact-name lookup on 2026-09-17); **Home Assistant's native MCP server (home-assistant org) is not in the registry** — the dump holds four third-party entries only: `io.github.Coolver/home-assistant-mcp` 3.2.12 (npm 192 dl/wk), `io.github.homeassistant-ai/ha-mcp` 8.5.0 (2026-09-16), `io.github.Koneisto/HomeAssistant-Light-MCP` 0.6.1, `io.github.daedalus/mcp-homeassistant` 0.1.0.
4. **PulseMCP** is the only source with a usage-like metric (`visitorsEstimateMostRecentWeek/LastFourWeeks/Total`, "estimated visitors" of their own pages, i.e. a proxy, not installs). Its old `v0beta` API is being sunset ("September 2026: Fully sunset (100%)", observed HTTP 410); the `v0.1` API requires `X-API-Key` + `X-Tenant-ID` obtained by e-mailing hello@pulsemcp.com, with limits 200/min, 5,000/h, 10,000/day. The website blocks curl (Cloudflare 403) but renders for a browser/WebFetch; server pages show "Est. Visitors", rank and stars.
5. **Glama** `https://glama.ai/api/mcp/v1/servers` needs an API key (`Authorization: Bearer`, 100 req/s per IP) and its API Data License requires "visible attribution to Glama on every page" and a per-record link — unusable inside an installer's TUI without attribution work. The reference docs do not name any popularity field.
6. **claude.com/plugins long tail = `plugin-details.json`.** The public website (Webflow CMS, `?cc61befa_page=N`, 100 cards/page, 3 pages = 300 cards) shows install counts that are consistently **~0.85–0.97 of** the values in `https://storage.googleapis.com/claude-code-dist-86c565f3-f756-42ad-8dfa-d59b1c096819/plugin-stats/plugin-details.json` (`installs_generated_at` 2026-09-11T06:00Z, `generated_at` 2026-09-17T07:36Z). The JSON has **308 plugins, 291 with `unique_installs`** (17 null), median 2,182, min 12 — this is the only complete, machine-readable, dated install-count source for the whole official marketplace and is what `claude plugin list --json --available` exposes as `installCount`. Use the JSON, not the website.
7. **Codex remote catalog has no popularity signal.** The `$CODEX_HOME/cache/remote_plugin_catalog/<hash>.json` (schema_version 1, 3,980 plugins, fetched_at 2026-09-17T03:50:58Z) has per-entry keys `id, name, scope, discoverability (LISTED 3,375 / UNLISTED 605), creator_account_user_id, creator_name, share_principals, share_url, can_publish_to_workspace, disabled_reason, installation_policy, installation_policy_source, must_show_installation_interstitial, authentication_policy, status, eligible_plan_types, release{version, display_name, description, keywords, interface{category, developer_name, website_url,...}, skills[], app_ids, app_manifest, app_templates, bundle_download_url, scheduled_tasks}`. No install/rating/rank keys (grep for `install_count` = 0 hits). The list order is server-curated (first 40: gmail, github, google-drive, outlook-email, canva, slack, hubspot, supabase, `app-69ea4ed2cf7c8191b742ef3622479ddd` (display_name Exa), notion, google-calendar, ..., vercel, sharepoint, teams, airtable, superhuman, wix, zoominfo) — position is a weak editorial signal at best. `codex plugin list --available --json` exposes even less (`pluginId,name,marketplaceName,version,installed,enabled,source,installPolicy,authPolicy`).
8. **skills.sh leaderboard JSON is gated** (`GET /api/v1/skills?view=all-time` -> 401 `authentication_required`, Vercel OIDC token). But the **HTML is server-rendered and scrapable**: repo pages (`https://www.skills.sh/<owner>/<repo>`) print `N total installs` and per-skill installs; the home page prints the all-time leaderboard with grouped rows ("+3 more from mattpocock/skills (4.0M total)"). The audit endpoint stays open: `curl -s https://skills.sh/api/v1/skills/audit/<owner>/<repo>/<skill>`.
9. **Ranking outcome** (formula in §8): popularity agrees with the current verdicts for 88 of 104 items. 16 disagreements: 9 "promote-candidates" (optional items in the top band: mattpocock-skills, example-skills, chrome-devtools-mcp plugin + MCP, github plugin, claude-mem marketplace, bun, rtk, claude-code-templates) and 6 "demote-candidates" plus 1 must-have not supported by popularity (`superpowers-marketplace`, 1,264 stars — but it is a dependency of elements-of-style/episodic-memory, so keep for functional reasons). **No item is audit-blocked**; superpowers, agent-browser, planning-with-files and gstack carry a Runlayer `fail` (warn-level gate, ×0.9).

## 3. Official MCP Registry — details

- **API versions.** `openapi.yaml` (`info.version: 1.0.0`) documents `/v0.1/servers`, `/v0.1/servers/{serverName}/versions`, `/versions/{version}` (`latest` allowed), `/v0.1/publish`, auth endpoints, `/v0.1/health`, `/v0.1/ping`. `/v0/servers` still returns 200 with the same shape (the schema URL inside entries is `https://static.modelcontextprotocol.io/schemas/2025-12-11/server.schema.json`).
- **Pagination.** `limit` 1..100 (default 30), `cursor` = `metadata.nextCursor` (e.g. `ac.snag/snag:1.0.0`, must be URL-encoded). Without `version=latest` every version of every server is returned (first page showed 4 versions of `ac.inference.sh/mcp`). With `version=latest`: 32,849 rows, 22,084 in the `io.github.*` namespace.
- **Search semantics.** "Search servers by name (substring match)" — name only, not title/description. Therefore exact-name lookups are the reliable path: `curl -s "https://registry.modelcontextprotocol.io/v0.1/servers/io.github.upstash%2Fcontext7/versions/latest"` (slash must be `%2F`). `com.github/github-mcp-server` -> 404; the real name is `io.github.github/github-mcp-server`.
- **Latency.** Exact-name lookups 0.5–0.8 s; some substring searches took 19–23 s (playwright, grafana, kubernetes) — do not put substring search on the installer's hot path.
- **What the installer can use it for:** canonical `packages[]` (registryType npm/pypi/oci/mcpb + exact `version`, optional `fileSha256` for mcpb) and `remotes[]` (transport + URL) to validate that a hand-written `claude mcp add`/`codex mcp add` line matches the publisher's manifest, plus `status=deprecated` and `updatedAt` as staleness gates. Not for popularity.
- **Consumers.** README credits Tadas Antanavicius (PulseMCP) as a maintainer; the ecosystem-vision doc names Smithery and PulseMCP as subregistries "providing curation, or extending it with additional metadata". PulseMCP's v0.1 API "implements the Generic MCP Registry API specification" (same `/v0.1/servers` shape plus `_meta["com.pulsemcp/server"]`). That is the recommended way to get "registry + popularity" in one call — but it needs a key.

## 8. Ranking method (repeatable)

Inputs per item (all dated in the CSV): GitHub stars `S`, weekly downloads `D` (npm last-week or pypistats last_week), installs `I_c` (Anthropic catalog `unique_installs`) and `I_s` (skills.sh repo total installs), last activity `T = max(last commit on default branch, latest package publish, catalog last_updated)`, audit status, archived flag.

1. **Log-normalise within class** (classes: agent, marketplace, plugin, skill, mcp, tool, other-agent) so a 145k-star agent does not flatten a 5k-star MCP server:
   `s = log10(S+1)/max_class`, `d = log10(D+1)/max_class`, `i = max(log10(I_c+1)/max_class_c, log10(I_s+1)/max_class_s)` (the two install sources are normalised separately because skills.sh counts every skill of a pack).
2. **Popularity** `P = (0.35·s + 0.35·d + 0.30·i) / Σ(weights of signals present)` — missing signals do not penalise, they are just absent (an official Anthropic plugin has only `i`).
3. **Recency multiplier** `R` from age of `T`: ≤90 d 1.0; ≤180 d 0.9; ≤365 d 0.75; >365 d 0.5; archived repo 0.5 (none in scope).
4. **Audit multiplier** `A`: 1.0 pass/unaudited-non-skill; 0.95 any warn; 0.9 Runlayer fail; 0 (BLOCK) Gen/Snyk/Socket fail.
5. `score = 100 · P · R · A`. Bands: **top ≥ 85, mid 60–84, tail < 60.**
6. **Flags vs. current verdict** (from the digests/manifest): `promote-candidate` = optional/skip item in *top*; `demote-candidate` = recommended item in *tail*; `popularity-does-not-support-must-have` = must-have in *tail*; `AUDIT-BLOCK`. The flags are inputs to a relevance decision, not automatic verdict changes — popularity says nothing about whether the user needs Proxmox, Home Assistant or Bun.

Re-run: `python3 scratchpad/g7/gh_snapshot.py && python3 scratchpad/g7/rank.py` after refreshing `npm_dl.tsv`, `npm_latest.tsv`, `plugin-details.json` and the `skillssh_*.html` pages with the commands in §2 (rows 5, 10, 12, 14). Runtime ≈ 4 min (GitHub HTML 66 × 1.5 s dominates); zero `api.github.com` calls.
