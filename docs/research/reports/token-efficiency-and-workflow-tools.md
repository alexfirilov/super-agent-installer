## 0. Corrections vs. the earlier partial draft

1. **Codex hooks need no feature flag any more.** Official hooks doc: "Hooks are enabled by default. To disable them, add `[features] hooks = false`". What `caveman setup --agent-native codex` actually writes (read from `@caveman-ai/cli` 1.3.3 `dist/index.js`, function `codexNativeMutations`/`codexNativeConfig`/`nativeHooksDocument`): see section 1.5. ### 1.4 Codex support (answer to "does it support Codex hooks now that Codex has hooks?")
- **Yes, via `caveman setup --agent-native codex`** (CLI >= 1.3.x). Verified in `@caveman-ai/cli` 1.3.3 `dist/index.js`: `codexHooksPath()` = `~/.codex/hooks.json`; `nativeHooksDocument("codex", ...)` registers `native-hook:codex` entries on the 12 Codex events listed above, "Replace, never accumulate" (identity-matched so upgrades don't stack). CLI 1.3.3 also adds the shrink hook to Codex `PreToolUse` (`includeShrink = true` in `codexNativeMutations`). **Verified in the 1.3.4 tarball (`dist/index.js`, 2026-09-17):** the *wrap* path now excludes Codex (`includeShrink = !opts.noShrink && wrapCompressEnabled(opts) && agent?.id !== "codex"`), but the *agent-native* path calls `nativeHooksDocument("codex", nativeShrinkEnabled(), ...)` where `nativeShrinkEnabled()` reads the `think.shrink` capability, **default `true`** — so `caveman setup --agent-native codex` on 1.3.4 still writes `caveman shrink-hook` into Codex `PreToolUse` unless `think.shrink` is off first (`caveman tools config set think.shrink off`, by analogy with the documented `think.core` toggle; env form `CAVEMAN_SHRINK`). The README says "Codex skips the shrink hook because its runtime rejects the rewrite (openai/codex#18491)", so an installer should turn `think.shrink` off before running agent-native codex. Also note caveman's Codex event list (12: includes `PostToolUseFailure`, omits `Interrupt`) differs from the Codex hooks doc list (12: `SessionStart, SessionEnd, PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, UserPromptSubmit, SubagentStart, SubagentStop, Stop, Interrupt`) — the extra key is ignored, not harmful. `caveman codex` (wrap) instead builds an **ephemeral `CODEX_HOME`** with its own `config.toml` + `hooks.json`, symlinking the real `skills` and `AGENTS.md` read-only.
- Skill route: `npx skills add ... -a codex` (per-session `/caveman`), no hooks.
- Proxy: `caveman codex` (README agent table: "env vars (API key) · ephemeral `CODEX_HOME` (ChatGPT login)").
- Not on Windows: "Codex hooks are currently disabled on Windows" (docs/install-windows.md).
- Codex-side prerequisite: hooks are on by default (0.154.0) but **must be trusted in `/hooks`** before they run.
- Not verified locally (this machine has no `~/.codex/hooks.json`; the user has not run agent-native codex).

### 1.5 What agent-native writes (for the installer's idempotency/backup plan)
From CLI 1.3.3 dist (functions `codexNativeConfig`, `codexNativeMutations`, `nativeHooksDocument`, `installShrinkHookCodex`):
- `~/.codex/hooks.json`: merged, JSON-pretty, mode 0600; each event gets `{ "hooks": [{ "type": "command", "command": "'<~/.caveman/bin/caveman-proxy>' native-hook codex --adapter '<npm-global>/@caveman-ai/cli/dist/native-hook-fast.js'", "timeout": 30 }] }`.
- `~/.codex/config.toml`: wrapped in marker blocks `# >>> caveman:native-root` … (`model_provider = "caveman"`) and `# >>> caveman:native-tables` … (`[model_providers.caveman]` pointing at the local gateway route `/chatgpt` for subscription login or `/w/codex` for API key, plus `[mcp_servers.caveman] command = "<~/.caveman/bin/caveman-mcp>"`). It strips its own prior blocks first; if markers are corrupted it aborts with "run `caveman doctor codex`". It does **not** touch `[features]`.
- Journaled ("journals bundle ownership, validates installed components, and rolls back failed installs. Rerunning converges journal-owned drift"), removed with `--remove` ("restore prior skill/MCP bytes").
- Consequence: after agent-native, **all Codex traffic is routed through the caveman local gateway**. If the user runs Codex with a different `model_provider` (e.g. a corporate proxy) this conflicts; the installer should ask before enabling it and keep `caveman codex` (ephemeral home) as the non-invasive option.

### 1.7 Wiring caveman into Claude Code settings.json (what the installer should template)
Observed on this machine after `caveman setup --agent-native claude` (all entries `"type":"command"`, `"timeout":30`):
```json
{
  "hooks": {
    "SessionStart": [{"hooks":[{"type":"command","command":"'/home/alexf/.caveman/bin/caveman-proxy' native-hook claude --adapter '/usr/local/lib/node_modules/@caveman-ai/cli/dist/native-hook-fast.js'","timeout":30}]}],
    "UserPromptSubmit": [ ...same command... ],
    "PreToolUse": [
      {"hooks":[{ ...same command... }]},
      {"hooks":[{"type":"command","command":"'/usr/local/bin/caveman' shrink-hook","timeout":30}]}
    ],
    "PostToolUse": [...], "PostToolUseFailure": [...], "PreCompact": [...],
    "SubagentStart": [...], "SubagentStop": [...], "Stop": [...], "SessionEnd": [...]
  },
  "statusLine": {
    "type": "command",
    "command": "bash \"$(ls -td \"$HOME/.claude/plugins/cache/caveman/caveman/\"*/ 2>/dev/null | head -1)src/hooks/caveman-statusline.sh\""
  }
}
```
Recommendation: **do not hand-template the native-hook entries** (absolute paths to `~/.caveman/bin` and the npm global `dist/` differ per host/OS and the CLI replaces its own entries by identity on upgrade). Run `caveman setup --agent-native claude` (or the release installer `install.sh`/`install.ps1`, which wires hooks + statusline badge and is "safe to re-run"). Hand-template only the `statusLine` when none exists. Manual statusline forms from `src/hooks/README.md`:
```json
{"statusLine":{"type":"command","command":"bash /path/to/caveman-statusline.sh"}}
{"statusLine":{"type":"command","command":"powershell -ExecutionPolicy Bypass -File C:\\path\\to\\caveman-statusline.ps1"}}
```
If a statusline already exists (claude-hud / ccstatusline / ccusage), caveman "does not overwrite it"; add the badge snippet from `src/hooks/README.md` (reads `session_id` from stdin JSON, checks `$CLAUDE_CONFIG_DIR/.caveman-sessions/<sid>.mode`, falls back to `.caveman-active`). The standalone `src/hooks/install.sh` merges with node, backs up settings.json once, and skips statusline if one is present.

Codex wiring for the installer: (1) `npx skills add JuliusBrussee/caveman -a codex -g` (safe everywhere); (2) optional `caveman setup --agent-native codex` (Linux/macOS only; rewrites `model_provider`; ask first; run `caveman tools config set think.shrink off` beforehand so 1.3.4 does not also write the Codex shrink hook — see 1.4); (3) optional shell alias `codex` -> `caveman codex` for proxy compression without touching `~/.codex`; (4) after any hooks are written: `codex` -> `/hooks` -> trust.

### 1.8 Is caveman still the leading token-saver?
By stars yes (106k) and by breadth (skill + proxy + hooks + MCP + memory + cloud). The field is now layered rather than substitutable (per the JetBrains and pasqualepillitteri comparisons): caveman shortens what the model *writes*; rtk (80.7k) compresses shell output; headroom (72.5k) compresses tool output at the API boundary; pxpipe (7.4k) images old context; context-mode (23.2k) sandboxes tool output in MCP subprocesses; claude-mem (94.1k) is memory, not compression. Independent A/B data (JetBrains, July 2026) shows small real-world effects for both caveman (8.5% output tokens) and rtk (+7.6% cost at low effort, +0.1% at high) — the installer should present these as opt-in with honest expectations. Stacking multiple PreToolUse Bash rewriters (rtk, caveman shrink-hook, token-optimizer, headroom's `headroom-rtk-rewrite.sh`) is untested; pick one.

## 2. Token-saver alternatives (detail)

### rtk — "Rust Token Killer" (rtk-ai/rtk)
- 80.7k stars (github.com 2026-09-17), Apache-2.0, default branch `develop`; latest stable **v0.49.0** (2026-09-11; `releases/latest` redirect confirmed 2026-09-17), nightly `dev-0.50.0-rc.439` (2026-09-14). npm package `rtk` (4.2.0, cliffano/rtk) is unrelated — do not `npm i -g rtk`.
- Claim: "reduce LLM token consumption by 60-90% on common dev commands"; single Rust binary, 100+ commands.
- Install (README, verbatim): `curl -fsSL https://raw.githubusercontent.com/rtk-ai/rtk/refs/heads/master/install.sh | sh`; `brew install rtk`; `cargo install --git https://github.com/rtk-ai/rtk`; Windows `winget install rtk-ai.rtk` (package exists in microsoft/winget-pkgs `manifests/r/rtk-ai/rtk`, but the newest manifest there is 0.46.0 vs release v0.49.0 and the README does not document winget — prefer the release zip `rtk-x86_64-pc-windows-msvc.zip` for the current version).
- Wiring: `rtk init -g` (Claude Code, PreToolUse hook rewriting Bash via `updatedInput` + `RTK.md`); `rtk init -g --codex`; `rtk init -g --gemini`; `rtk init -g --agent cursor|windsurf`; restart agent after.
- Independent measurement (JetBrains blog, July 2026, Claude Code 2.1.201, 86 tasks, Wilcoxon paired): low effort "median +7.6% more expensive per task (p=0.004)", "+13.8% more turns (p=0.03)"; high effort "+0.1% (p=0.99)"; "rtk's hook only touches about 20% of tool output; Claude Code already truncates pathological outputs; cached re-reads … bill at 1/10th price".
- Verdict: **optional** (was "recommended" in the draft; downgraded on the JetBrains data). Cross-platform and tiny, so fine to offer, but off by default and never stacked with caveman shrink-hook.

### headroom (headroomlabs-ai/headroom; PyPI `headroom-ai`)
- 72.5k stars (github.com 2026-09-17), Apache-2.0; PyPI 0.37.0 (2026-08-27), `requires_python >=3.10`; npm `headroom-ai` (TypeScript lib). Releases: v0.37.0 (Aug 27, "Windows process tree termination fix"), v0.36.5, v0.36.4 (Codex tool handling fixes); rtk integration "Removed in v0.34.0 alongside lean-ctx CLI tools".
- Claim: "20% fewer tokens for coding agents, 60-95% fewer tokens for JSON, same answers"; benchmarks 21%/57%/42%/30% on four scenarios.
- Install (README verbatim): `pip install "headroom-ai[all]"`; `uv tool install --python 3.13 "headroom-ai[all]"`; `npm install headroom-ai`.
- Wiring: `headroom wrap claude` (README agent table lists optional flags `--memory` · `--code-graph` · `--1m` · `--tool-search`; the combined one-liner in the earlier draft was assembled from that table, not copied); `headroom wrap codex` ("shares memory with Claude"); undo with `headroom unwrap <tool>`; both "start a local proxy, install Serena for semantic code navigation, and launch the agent configured to route through Headroom"; alternative `headroom proxy --port 8787` + `ANTHROPIC_BASE_URL=http://127.0.0.1:8787` (note: Claude Code docs say a custom `ANTHROPIC_BASE_URL` "pointing to a non-first-party host" disables MCP tool search; docs/remote-control (primary, confirmed 2026-09-17): Remote Control is unavailable when `ANTHROPIC_BASE_URL` points at a host other than `api.anthropic.com` "such as an LLM gateway or proxy" since v2.1.196 — headroom issue #1779 reports the same).
- Companion **headroom-desktop** (gglucass, 556 stars, MIT shell, "requires paid subscription to operate"): macOS 14+/Windows 10+/Linux glibc 2.39+; `brew install --cask headroom`; adds a `PreToolUse` hook + `~/.claude/hooks/headroom-rtk-rewrite.sh` for Claude and a provider block in `~/.codex/config.toml` + `OPENAI_BASE_URL` -> `127.0.0.1:6767` for Codex.
- Update (README verbatim): `headroom update` ("detects pip / pipx / uv tool and upgrades in place"; `headroom update --check`, `--pre`); for uv-tool installs `uv tool upgrade headroom-ai` also works.
- Verdict: **optional** — same layer as the caveman proxy (choose one); needs Python/uv (uv missing on this host); proxy mode breaks tool search and remote control.

### context-mode (mksglu/context-mode)
- 23.2k stars (2026-09-17); npm `context-mode` 1.0.169 (2026-06-29); Elastic License 2.0.
- Claim: "315 KB becomes 5.4 KB. 98% reduction" (sandboxed tool output), SQLite/FTS5 session continuity across compaction; 17–18 platforms.
- Claude Code: `/plugin marketplace add mksglu/context-mode` then `/plugin install context-mode@context-mode` (hooks injected automatically); verify `/context-mode:ctx-doctor`.
- Codex (README@main, corrected 2026-09-17): **primary path is a Codex plugin** — `codex plugin marketplace add mksglu/context-mode`, then install from `/plugins`; the plugin manifest "provides MCP via `.codex-plugin/mcp.json`, skills via `skills/`, and bundled hooks via `.codex-plugin/hooks.json`. No manual `[mcp_servers.context-mode]` block or `$CODEX_HOME/hooks.json` is needed". README still tells you to set `[features] plugin_hooks = true` + `hooks = true`; on Codex 0.154.0 `hooks` is on by default and `plugin_hooks` is **removed** (plugin-bundled hooks now load by default per the hooks doc, subject to `/hooks` trust). The manual fallback ("for Codex builds without `plugin_hooks`") is `npm install -g context-mode` + `[mcp_servers.context-mode] command = "context-mode"` + `[mcp_servers.context-mode.env] CONTEXT_MODE_PLATFORM = "codex"` + `~/.codex/hooks.json` entries running `context-mode hook codex <event>`. Needs `node` on the Codex process PATH; `CONTEXT_MODE_DIR` for a custom store.
