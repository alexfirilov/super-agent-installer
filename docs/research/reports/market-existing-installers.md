# Market survey: does an "all-in-one AI coding agent installer/manager" already exist? (as of 2026-09-16)

Researcher area: existing installers / managers for Claude Code + Codex CLI (+ plugins, skills, MCP) — scored against R1..R7. This is the completed version of an earlier partial report; everything kept from it was re-checked against fetched sources on 2026-09-16, and the gaps (agents-cli, kasetto, x0c/agentsync, agent-ready, codex-plugin-cc, scoop/winget package state, Codex skills-root question, rulesync global mode, spec-kit codex support) were filled.

Requirements legend:
- R1 installs Claude Code AND Codex CLI via official installers
- R2 installs plugins / skills / MCP servers for both
- R3 Linux AND Windows
- R4 interactive picker, default = all
- R5 in-place update of agents + plugins + skills + MCPs
- R6 self-updating script
- R7 profiles / reusable across many hosts

All popularity numbers were observed on 2026-09-16 (GitHub stars via api.github.com where available, otherwise img.shields.io `github/stars` badge JSON, which rounds to "1.4k"-style values; npm weekly downloads via api.npmjs.org `downloads/point/last-week`; PyPI via pypistats `last_week`). "unknown" means I could not fetch it. GitHub unauthenticated API was rate-limited during the second pass, so several star counts are shields.io-rounded.

## 1. Bottom line

**The exact thing does not exist.** Nothing found installs both agents through their official native installers on Linux AND Windows, then provisions plugins + skills + MCP for both agents, with an interactive default-all picker, in-place update of everything, self-update and host profiles.

**Closest overall:** `phnx-labs/agi-cli` (repo renamed from `phnx-labs/agents-cli`, which now 301-redirects; npm package still `@phnx-labs/agents-cli`, binary `agents`/`ag`, v1.22.117, 21 stars, 6,985 weekly npm downloads). It installs and version-pins Claude Code, Codex, Cursor, OpenCode, Grok and others (`agents add claude@latest`, `agents add codex@latest`), syncs skills/commands/rules/hooks/MCP/plugins from `~/.agents/` into each agent's native format, updates harnesses (`agents update codex`), self-updates (`agents upgrade`), has `agents setup` (interactive, idempotent) and a fleet profile (`agents.yaml` `fleet:` block + `agents fleet apply` over SSH). It fails R1 (installs harnesses by `npm install @anthropic-ai/claude-code@<release>` into isolated version homes, not the vendor native installer) and R3 (macOS/Linux; "Windows via WSL works but isn't first-class yet"), and it is a heavy opinionated harness (shims, clones a system repo with hooks into `~/.agents/.system/`, fleet, teams, menubar).

**Closest declarative config manager:** `pivoshenko/kasetto` (Rust, v3.8.0, 199 stars): one YAML (`kasetto.yaml` + `kasetto.lock`, `extends:` inheritance, remote config URL) → skills, MCPs, commands, instructions for Claude Code, Codex and 21 other agents; macOS/Linux/Windows single binary (`curl -fsSL kasetto.dev/install | sh`, `irm kasetto.dev/install.ps1 | iex`, scoop, brew, cargo); `kst sync --update`; `kst self update`; secrets injection from 1Password/Vault/pass/Keychain. Does not install agents or agent plugins/marketplaces, no interactive picker.

**Recommendation for the new script:** do not adopt agents-cli or any framework as the base (they replace the vendor install path and pull in a large opinionated runtime). Compose the vendor installers and the native `claude`/`codex` subcommands (install, update, plugins, marketplaces, MCP, doctor) with the `skills` CLI for skills; keep the picker / profiles / self-update logic in the script itself (they are small). If a declarative manifest is wanted later, kasetto's `kasetto.yaml` + lock design (or spxrogers/agentsync's TOML) is the format to copy or shell out to.

## 2. Official install / update surfaces (the ground truth the script must call)

Plugin / MCP / import CLI (from `claude --help` on 2.1.273, local):
```bash

claude plugin install|i <plugin[@marketplace]> [--json] [-y] [-s user|project|local] [--config key=value] [--accept-command <sha256>]   # -y is REQUIRED when stdin/stdout is not a TTY for command-source plugins
```

Skills: Claude Code personal skills live only in `~/.claude/skills/<name>/SKILL.md` (docs "where skills live" table; no `~/.agents/skills` root). Reserved folder name `synced` (claude.ai-downloaded skills).

Skills (source: build-skills.md, fetched): Codex reads `$CWD/.agents/skills` up to `$REPO_ROOT/.agents/skills` (REPO), **`$HOME/.agents/skills` (USER)**, `/etc/codex/skills` (ADMIN), plus built-in SYSTEM skills cached at `$CODEX_HOME/skills/.system` (source `codex-rs/skills/src/lib.rs`: `install_system_skills` writes to `CODEX_HOME/skills/.system`). The built-in `$skill-installer` skill installs curated skills from `openai/skills` into `$CODEX_HOME/skills` (local `~/.codex/skills/.system/skill-installer/SKILL.md`). Disable a root with `[[skills.config]] path=... enabled=false`. Official marketplace: `github.com/openai/plugins` (6.9k stars) whose `.agents/plugins/marketplace.json` is named `openai-curated` and lists 65 plugins including `superpowers`, `github`, `figma`, `notion`, `linear`, `vercel`, `codex-security`. The `openai-templates` and `plugin-management` plugins cached locally under `~/.codex/plugins/cache/openai-curated-remote/` are proprietary OpenAI remote plugins (plugin.json: "Discover relevant plugins and manage app connections, permissions, and dependencies") — a discovery/UX plugin, not a bootstrap tool.

Official "setup" tooling verdict: Anthropic's `claude-code-setup` plugin is a read-only *recommender* skill ("analyzes but doesn't modify files"); `claude import codex` only pulls config from Codex into Claude Code; `codex doctor` is diagnostics. OpenAI's `openai/codex-plugin-cc` (33k stars, official; `/plugin marketplace add openai/codex-plugin-cc` then `/plugin install codex@openai-codex`) has `/codex:setup` which "checks whether Codex is installed and authenticated. If Codex is missing and npm is available, it can offer to install Codex for you" via `npm install -g @openai/codex` — the only vendor tool that installs the *other* agent, and it uses npm, not the native installer. None is an installer for both.

### Resolved: which folder Codex loads user skills from
Official docs: `$HOME/.agents/skills` is the USER root. The `skills` CLI's canonical global store is also `~/.agents/skills/` (README "Installation Methods": symlinks from each agent dir to a canonical copy), and it symlinks `-a codex` targets into `~/.codex/skills/` (README supported-agents table: Codex global path `~/.codex/skills/`). kasetto instead writes Codex skills straight to `~/.agents/skills/`. Consequence for the script: any skill installed globally with `npx skills add -g` is already visible to Codex through `~/.agents/skills` without `-a codex`; adding `-a codex` creates a second copy in `~/.codex/skills/` (the docs say same-name skills are not merged and "both can appear in skill selectors"), so prefer `-a claude-code` only (Claude Code reads only `~/.claude/skills`) and let Codex pick up the canonical dir. On this machine that is exactly the state: 21 skills in `~/.agents/skills` (lock v3), only `find-skills` symlinked into `~/.claude/skills`, `~/.codex/skills` holds just `.system`.

## 4. Notes per important candidate

### phnx-labs/agi-cli (formerly agents-cli) — the closest thing
- README (raw main, fetched 2026-09-16): "One CLI for all your AI coding agents - versions, config, cloud dispatch, sessions, and teams". Quickstart: `npm install -g @phnx-labs/agents-cli` (or `curl -fsSL agi-cli.sh | sh`, `bun install -g`), `agents setup` ("interactive and idempotent -- safe to re-run on any machine"; in non-TTY prints checklist), `agents add claude`, `agents add codex@latest`, `agents use claude@2.0.65 -p` (writes `agents.yaml`), `agents update codex [--check]`, `agents upgrade` (self), `agents doctor`, `agents import` ("adopts an existing unmanaged install"), `agents install mcp:com.notion/mcp`, `agents skills add gh:...`, `agents plugins add <name>@<git url>` (mirrored into `<home>/.claude/plugins/marketplaces/agents-cli/` + `enabledPlugins`), `agents repo push/pull`, `agents fleet apply [--plan]`.
- Install mechanism (cli/docs/version-management.md): `npm install @anthropic-ai/claude-code@<release>` into `versions/claude/<ver>/node_modules/.bin/claude`; latest resolved from npm (`getLatestNpmVersion`); shims route by `agents.yaml`. "Self-updating harnesses have one current binary" (concepts.md). Uninstall prints `npm uninstall -g @phnx-labs/agents-cli`.
- Compatibility: "macOS and Linux. Windows via WSL works but isn't first-class yet." Codex capability gates: hooks ≥0.116, plugins ≥0.128, commands converted to skills ≥0.117.
- Risk: `agents setup` clones `phnx-labs/.agents-system` (hooks) into `~/.agents/.system/` and fast-forwards it on `agents use`; opt out with `--no-system-repo` or `AGENTS_SYSTEM_REPO`. Note it also claims `~/.agents/` as *its* user repo — the same directory the `skills` CLI uses as canonical skill store and Codex uses as USER skills root.
- Verdict: proves the concept but conflicts with R1 (native installers) and R3 (Windows), and its scope is far beyond an installer. Use as a design reference for `agents.yaml` fleet profiles and `doctor --check` drift gating.

### pivoshenko/kasetto
- README (raw main): "declarative AI agent environment manager, written in Rust"; `kst init [--global]` (global config `~/.config/kasetto/kasetto.yaml`), `kst add <repo>[@ref] [--skill x --mcp y --command z --instruction w]`, `kst sync [--update|--locked] [--config <url>]`, `kst lock [--check]`, `kst list --json`, `kst self update` ("fetch latest release, verify SHA256, replace binary in place"), `kst self uninstall`. Lock-first like cargo/uv. Secrets `${kst_...}` resolved from env/1Password/Vault/AWS/GCP/Azure/KeePassXC/pass/Keychain at sync time.
- Installers: `curl -fsSL kasetto.dev/install | sh`; `powershell -ExecutionPolicy Bypass -c "irm kasetto.dev/install.ps1 | iex"`; `brew tap pivoshenko/tap && brew trust pivoshenko/tap && brew install kasetto` (README has the `brew trust` step); `scoop bucket add kasetto https://github.com/pivoshenko/scoop-bucket && scoop install kasetto`; `cargo install kasetto`.
- Agent paths: Claude Code `~/.claude/skills/`, Codex `~/.agents/skills/` (matches official Codex docs). Its own "vs alternatives" page compares only Vercel Skills, Claude plugin marketplaces, dotfiles symlinks and manual copying — it does not claim to install agents or agent plugins.
- Verdict: best fit for a future "manifest" layer (R7) if the script wants declarative reproducibility beyond the `skills` lockfile; would still need the script for R1/R4/R5(agents,plugins)/R6.

### vercel-labs/skills
- README (raw main): supports OpenCode, Claude Code, Codex, Cursor "and 75 more" (79 agents). Global paths: Claude Code `~/.claude/skills/`, Codex `~/.codex/skills/`, canonical copy `~/.agents/skills/` (symlink default; `--copy` for Windows/no-symlink).
- Key commands (verified with local `npx --no-install skills --help`, which is 1.5.23 on this machine; npm latest is 1.6.0 published 2026-09-17T00:01Z, dispatch table read from the 1.6.0 tarball): `add <src> [-g] [-a <agents>] [-s <skills>] [-l] [-y] [--copy] [--all] [--full-depth]`; `use`; `remove`; `list|ls`; `find [--owner]`; `update|upgrade [-g|-p] [-y]`; `experimental_install` (restore from `skills-lock.json`); `init`; `experimental_sync`. **There is no `sync` command** (only `experimental_sync`); 1.6.0's dispatch table has an undocumented `check` case that routes to the same `runUpdate` handler as `update`/`upgrade` (not in `--help`), so treat `check` as an alias of `update`, not a dry-run.
- Also discovers skills declared in `.claude-plugin/marketplace.json` / `plugin.json`, so Claude-plugin repos work as skill sources for Codex.
- Telemetry on by default (`DISABLE_TELEMETRY=1` / `DO_NOT_TRACK=1`); uses `gh` / git credentials for private repos.
- skills.sh install counts are internally inconsistent (front page vs skill pages); treat as approximate.

### claude-code-templates (aitmpl)
Claude-only ("Ready-to-use configurations for Anthropic's Claude Code"); installs into project `.claude/` (agents/commands/mcps/settings/hooks/skills), `--directory` to retarget; no Codex; Windows only mentioned for python detection. `--plugins` dashboard, `--health-check`, `--analytics` are side tools. Not useful as a provisioning building block.

### rulesync vs ruler
Both are "single source → many agents" generators, project-first. Rulesync's global-mode guide (fetched 2026-09-16) says global mode "supports rules generation for Claude Code, GitHub Copilot, and OpenCode" and "Command generation in global mode remains Claude Code only" — so no global Codex MCP/skills/hooks; Codex CLI is covered only at project scope. Ruler propagates MCP into `.mcp.json` and `.codex/config.toml` at project scope and has `revert`. Neither installs agents, plugins, or skills from marketplaces.

### MCP managers
- `add-mcp` is the only MCP tool that natively writes both `~/.claude.json` and `~/.codex/config.toml` with `-g`; flags `-a`, `-y`, `--all`, `--transport http|sse`, `--auto-approve` (Codex, Claude Code); also `list`, `remove`, `sync`, `find`. Windows not documented.
- `mcpm` README's client list still omits Claude Code and Codex, but the roadmap item "[x] Additional client support (gemini-cli, codex, etc.)" is checked and `src/mcpm/clients/client_registry.py` registers `claude-code` (`ClaudeCodeManager`, `~/.claude.json`) and `codex-cli` (`CodexCliManager`, `~/.codex/config.toml`, key `mcp_servers`). So it does work for both agents; drawbacks are Python, last release 2.15.0 (2026-05-22), last commit May 2026.
- Docker MCP gateway supports `claude-code` and `codex` client names but requires Docker (Desktop 4.62+ or CE with `DOCKER_MCP_IN_CONTAINER=1`).
- wyattjoh/mcp-manager (Claude Code + Claude Desktop only, last commit Aug 2025) and "MCP-Club/mcpm" (Claude Desktop) are stale/irrelevant; no Glama or PulseMCP CLI that writes Claude Code / Codex config was found.

### Update-all tools
- `aiupdate` is exactly the R5 loop, in ~40 lines of config: concurrent `claude update`, `codex update`, …, `npx skills update -g -p -y`, skipping tools not installed. Node package (`npx aiupdate`), 13 stars.
- `agentup` (Go) adds install-method detection (npm/pnpm/yarn/brew/winget/scoop), Windows support and self-update from GitHub Releases (R6 pattern) but is tiny (2 stars, Chinese README). GitHub release v0.3.0 exists; installers `curl -fsSL https://raw.githubusercontent.com/rockychang7/agentup/main/install.sh | bash` / `irm https://raw.githubusercontent.com/rockychang7/agentup/main/install.ps1 | iex`; self-update is `agentup update` (alias `agentup upgrade agentup`), verifying SHA-256 against `checksums.txt`; harness updates `agentup upgrade [codex|claude-code|opencode|agy]`.

### Config-as-code
- `spxrogers/agentsync` is the most complete "dotfiles for agents" tool: `~/.agentsync/` TOML/JSON → per-agent native formats (MCP with secret vault, memory, skills, subagents, commands, hooks), installable via brew tap / scoop bucket / choco / deb / rpm. It does not install agents or plugins from marketplaces and has no built-in multi-host sync ("use chezmoi").
- `x0c/agentsync` (Go, single binary, Windows amd64 release) keeps `~/.config/agentsync/{AGENTS.md,mcp.json,skills/,sync-policy.json}` canonical and symlinks `~/.codex/AGENTS.md`, `~/.claude/CLAUDE.md`, `~/.codex/skills`, `~/.claude/skills`; MCP configs are rewritten (cannot be symlinks) with `--watch`; "Windows tries symlinks first, then hardlinks, then a managed copy with a marker comment"; only touches runtimes whose home dir exists; backs up before replacing.
- Nix home-manager gives R2 + R7 declaratively but Linux/macOS only and installs the nixpkgs build, not the vendor installer.
- chezmoi pattern (zurfyx/dotfiles): `dot_claude/modify_settings.json` and `private_dot_codex/modify_private_config.toml` merge only the keys worth carrying into files the agents own and rewrite; `exact_` skill dirs delete removed skills. Useful for the script's "settings" step: never overwrite `~/.claude/settings.json` / `~/.codex/config.toml` wholesale; merge (jq / a TOML-aware tool).

### Windows package state (verified 2026-09-16)
- winget: `Anthropic.ClaudeCode` 2.1.268 (publisher Anthropic PBC; documented by Anthropic), `OpenAI.Codex` manifests up to 0.152.0 (not in OpenAI's README, which lists install.ps1, npm, brew).

## 5. Recommended building blocks for the new script

1. **Agent install/update**: vendor installers (`claude.ai/install.sh|.ps1|.cmd`, `chatgpt.com/codex/install.sh|.ps1`), then `claude update` / `codex update`; fallbacks `scoop install claude-code codex` (current), `winget install Anthropic.ClaudeCode` / `winget install -e --id OpenAI.Codex` (lag), `brew install --cask claude-code@latest` / `brew install --cask codex` on macOS. Verify with `claude --version`, `claude doctor`, `codex --version`, `codex doctor --json`.
2. **Plugins**: `claude plugin marketplace add <src>` + `claude plugin install <p>@<mkt> --json` and `claude plugin update <p>`; `codex plugin marketplace add <src>` + `codex plugin add <p>@<mkt> --json` and `codex plugin marketplace upgrade`. Model the profile after `fcakyon/claude-codex-settings` (one marketplace repo consumed by both agents) — this is also how superpowers and BMAD are distributed to Codex now.
3. **Skills**: `npx skills add <repo> -g -a claude-code -s '*' -y [--copy on Windows]` (Codex reads the canonical `~/.agents/skills` itself; add `-a codex` only if you want the `~/.codex/skills` copy and accept duplicates); refresh with `npx skills update -g -y`; persist the lockfile `~/.agents/.skill-lock.json`; restore via `npx skills experimental_install` where a `skills-lock.json` exists. Optionally drive skills + MCP + instructions declaratively with `kasetto` (`kst sync --locked`) if a lock-first manifest is wanted.
4. **MCP**: prefer native `claude mcp add-json <name> '<json>'` and `codex mcp add <name> (--url | -- cmd)` so the script is the single source of truth; optionally `npx add-mcp <url> -g -a claude-code -a codex -y` for quick fan-out.
5. **Settings**: merge, never overwrite (`~/.claude/settings.json`, `~/.claude.json`, `~/.codex/config.toml`) — chezmoi `modify_` pattern; jq for JSON, a TOML-aware tool (python `tomllib`/`tomli_w`, or `codex config`-style edits) for Codex.
6. **Update-all loop**: reimplement `aiupdate`'s concurrent loop (claude update, codex update, plugin update/upgrade, skills update) — it is trivially small.
7. **Self-update**: `agentup`/`kasetto self update`-style release check against the script's own GitHub Releases (download, verify SHA256, replace in place); nothing off-the-shelf to reuse for a bash+PowerShell script.
8. **Profiles / hosts**: a YAML/TOML manifest in the spirit of `kasetto.yaml` (+ lock, `extends:`) or `agents.yaml` `fleet:` (agents-cli) or `~/.agentsync/` (spxrogers), stored in the dotfiles repo (chezmoi/yadm); `agents-cli`'s `doctor --check` drift gate is a good idea to copy. No existing tool provides host profiles for both agents through the vendor installers.
9. **Not recommended as dependencies**: agents-cli (npm-installs harnesses, WSL-only on Windows, heavy), claude-code-templates (Claude-only), mcpm (works for both agents but Python and stale since May 2026; native CLIs suffice), Smithery (hosted registry), frameworks (SuperClaude, ruflo, OMC/OMX, oh-my-openagent), mcp-get (deprecated), spec-kit (project scaffolding; it DOES have `--integration codex`), agent-ready (no Windows, no agent install).
